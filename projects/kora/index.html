A personal assistant needs more than a chat box.

The useful part is continuity: knowing what you are working on, finding the relevant context, and keeping the result somewhere you can use it again.

Kora brings conversations, personal knowledge, and structured work into a Windows application. A shared runtime connects the desktop interface, CLI, and Chrome extension, with durable state in SQLite.

What I built.

One runtime, several ways in.

I extended Pi’s open-source foundation with Kora’s tools, skills, personal context, and product services. The interfaces share behavior rather than each implementing a separate assistant.

Context with somewhere to live.

Persistent records and hybrid retrieval connect the assistant to personal knowledge and work. Keeping state locally makes it inspectable; model requests still use the configured provider.

Work that can continue.

Durable sessions and stored artifacts give the assistant a way to pick up existing work instead of starting every interaction from scratch.

Test the messy parts.

What happens when a plan changes halfway through the week?

I built an evaluation harness with simulated-user interactions, controlled event timing, changing workweek scenarios, and blinded review. It examines task completion, memory persistence, authorization boundaries, and recovery across restarts.

A changing week

  1. A person gives the assistant plans and constraints.
  2. New information changes what is feasible.
  3. A later interaction tests whether the assistant kept the right context.
  4. The review inspects the actual outcome, including missed work and recovery.

This is ongoing evaluation work. The interactive sample above demonstrates the interface; it does not run this evaluation or make a live agent request.

Built in the open.

Kora is in active development. The public repository contains the Windows app, runtime, and setup instructions, including its Pi-derived foundation and license notices.
